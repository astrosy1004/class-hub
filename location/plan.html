1. 기획서 검토

방향은 좋고, 결정 3가지를 반영했습니다

개발계획서(15개 장) · 목업 3장 · 보유 CSV를 검토하고, 확정한 선택에 맞춰 계획을 고쳐 구현했습니다.

그대로 가져간 것 유지

  • "숫자는 먼저 계산하고, AI는 문장만 만든다" 원칙
  • 모든 추천에 기준일 · 출처 · 한계 표시
  • 5개 항목 가중합 입지 적합도, "조건부 추천" 등급
  • 시간대 · 추이 · 연령 도넛 · 강점/위험/전략 구성 (목업)

확정한 결정 구현됨

  • ① 처음부터 동 단위 검색 ("연남동 카페") — 서울 427개 행정동
  • ② 조회 시점에 자료를 가져옴 — 경쟁 점포는 실시간 Kakao, 생활인구는 매일 모은 요약
  • ③ Kakao 지도 SDK 사용 (검색 · 지도 · 점포 · 현재 위치)

구현하며 바뀐 것 — 서울 API가 행정동 필터를 지원하지 않고 최근 2개월만 제공해, GitHub Actions가 매일 전 행정동을 받아 Firestore에 쌓는 수집기 구조로 바꿨습니다 (서버 · Blaze 요금제 불필요). 점수의 25구 백분위는 쓸 수 없어 수집된 427개 동의 기준 분포로 대체했습니다.

그 밖의 보완: 기획서의 무거운 스택(Next.js · FastAPI · PostGIS · Celery) 축소 · 일정과 완료 기준 신규 정의
