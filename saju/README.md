# 나의 기질 그래프 (사주 해석 웹앱)

생년월일시로 사주 명식을 계산하고, 인생 흐름을 그래프로 보여주는 웹앱입니다.
기획: `사주로 풀어보는 나의 기질 해석 앱 기획서.md` (1주 MVP 범위로 구현)

기술 구성은 `0930-weather-app/`(현장 날씨 안전도우미)과 같습니다.
순수 HTML·CSS·바닐라 JS(`<script type="module">`, 빌드 도구 없음), Firebase Auth(구글 로그인), Firestore, Firebase Hosting.

- Firebase 프로젝트: `saju-app-sykim` (표시 이름 `saju-app`, `saju-app` ID는 이미 다른 사람이 써서 사용 불가)
- 배포 주소(7단계 이후): https://saju-app-sykim.web.app

## 단계별 진행

## 실행 방법

`<script type="module">`을 쓰므로 반드시 로컬 서버로 실행합니다.

```bash
py -m http.server 5510 --bind 127.0.0.1
```

- 앱: http://localhost:5510 (저장된 명식이 없으면 기획서 예시 명식 "홍길동"으로 보여줌)
- 엔진 검증 페이지: http://localhost:5510/check.html

## 점수 엔진 (`js/score.js`, 규칙은 `js/score-rules.js`)

기획서 "해석 엔진 로직" 그대로: **용신에 가까울수록 높고, 기신에 가까울수록 낮다**. 같은 명식이면 항상 같은 점수.

1. 원국 분석: 자리별 무게(월지 3배) × 지장간 비중으로 나를 돕는 기운(비겁·인성) 비율 50% 이상이면 신강.
   겨울(亥子丑)생은 조후 용신 화, 여름(巳午未)생은 수. 그 외엔 신강이면 식상·재·관 중 가장 약한 것, 신약이면 인성.
   희신 = 용신을 생하는 오행, 기신 = 신강이면 인성·비겁(신약이면 재·관) + 용신을 극하는 오행.
2. 기본 점수: 천간 40% + 지지(지장간 비중) 60%, 용신 1 · 희신 0.6 · 한신 0 · 기신 -0.8 → 52 ± 34점
3. 영역 가중치: 영역별 십신 가중치 (재물 = 재성·식상 +, 비겁 - 등, 성별에 따라 연애·자식 다름)
4. 관계 보정: 일지(배우자궁) · 시지(자녀궁)와 육합 가점, 충 감점. 천간합으로 용신이 생기면(무계합화 등) 가점. 도화, 조후
5. 월운은 세운 35% + 월운 65%, 일진은 일진 70% + 월운 30%

기획서 예시(병진·신축·계유·신유)는 신강 · 조후 용신 화 · 희신 목 · 기신 금·수로 나와 기획서와 같습니다.
**규칙 숫자는 초안**이며, 기획서대로 출시 전 명리 전문가 검수로 `score-rules.js`를 보정해야 합니다.

### 운영 원칙 반영

- 모든 결과 화면 하단에 참고용 고지
- 재물: 종목·매수·매도 추천 없이 "투자 이유 · 세금 · 자금 용도" 점검 안내
- 마음: 외로움·무기력 요인 화면에 정신건강 위기상담(1577-0199) · 자살예방 상담전화(109) 안내
- 관계: "이혼수", "자식 복 없음" 같은 단정 표현을 문구에 쓰지 않음

## 만세력 계산 기준 (`js/manse.js`)

| 항목 | 기준 |
|---|---|
| 연주 | 입춘 **시각**에 해가 바뀜 (1984년 = 甲子) |
| 월주 | 12절(입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한) **시각**에 달이 바뀜. 甲己년은 丙寅월부터 |
| 일주 | 출생지 지방시 날짜 기준, **23시(자시 시작)부터 다음 날**. 2000-01-01 = 戊午일 |
| 야자시 옵션 | 켜면 23~24시는 일주를 그날로 두고, 시주만 다음 날 일간으로 계산 |
| 시주 | 지방시 2시간 단위. 서울(동경 126.98°)은 표준시보다 약 32분 늦게 바뀜 (자시 23:32~01:32) |
| 시간 모름 | 시주를 비우고 정오 기준으로 연·월·일주 계산 |
| 표준시 | 1908~1911, 1954-03-21~1961-08-09는 UTC+8:30, 나머지 UTC+9 |
| 서머타임 | 1948~1951, 1955~1960, 1987~1988 기간(`KOREA_DST`)이면 1시간을 빼고 계산. 끌 수 있음 |
| 음력 입력 | `lunar.js`로 양력으로 바꾼 뒤 계산. 없는 윤달·없는 날짜는 오류 문구 |
| 십신 | 지지는 정기(子=癸, 午=丁, 巳=丙, 亥=壬) 기준 |
| 대운 | 양남음녀 순행, 음남양녀 역행. 대운수 = 출생~절입 날수 ÷ 3, 반올림, 최소 1 |
| 대운 나이 | 세는 나이 기준. 현재 대운 = (올해 − 출생 연도 + 1)이 속한 대운 |

학파마다 다른 선택(대운수 반올림, 대운 개수, 기본 경도)은 `saju-data.js`의 `SETTINGS`에서 바꿉니다.

## 절기 정확도

`solar-terms.js`는 Meeus 『Astronomical Algorithms』 25장의 고정밀 방법(VSOP87 축약 계수 + 장동·광행차)과
ΔT 다항식으로 절입 시각을 계산합니다. 공개된 절입 시각 8건(2023~2026 입춘, 2024 춘분·하지·추분·동지)과
비교해 **최대 오차 0.6분**입니다. (처음 쓴 저정밀 식은 최대 10분 틀려서 바꿨습니다.)

## 한국 음력 (`js/lunar.js`)

음력표를 넣지 않고 천문 계산으로 만듭니다.

1. 합삭(새달) 시각을 Meeus 49장 공식으로 계산하고, 합삭이 든 **한국 표준시 날짜**를 초하루로 둡니다.
2. 동지가 든 달을 11월로 두고, 동지~다음 동지 사이에 달이 13개면 중기(우수·춘분·곡우…)가 없는 첫 달을 윤달로 둡니다.

중국 음력표(UTC+8 기준)를 쓰면 합삭이 한국시간 자정 근처인 달에 한국 음력과 하루씩 어긋납니다.
예: 1966년 설날 합삭은 한국시간 1월 22일 00:46이라 한국은 1/22, 중국은 1/21입니다.

검증: 설날 7개 해, 추석 3개 해, 윤달 13개 해(1995~2028)가 맞고, 1900~2100년 모든 날짜를 양력→음력→양력으로 왕복해 오류 0건입니다.

## 보정 안내 (`notices`)

결과가 갈릴 수 있는 경우 결과 위에 안내를 띄웁니다. 기준값은 `SETTINGS`에 있습니다.

| 경우 | 안내 |
|---|---|
| 서머타임 기간 출생 | 1시간을 뺐다는 안내 (끄면 보정하지 않았다는 안내) |
| 1954~1961년 등 UTC+8:30 시기 | 당시 표준시를 반영했다는 안내 |
| 시간을 입력함 | 출생지 경도로 지방시가 몇 분 다른지, 지방시 몇 시로 시주를 정했는지 |
| 시주가 바뀌는 시각 ±10분 | 출생 시각 확인 요청 |
| 23시대 출생 | 일주를 다음 날로 봤다는 안내 (야자시면 그 반대) |
| 절입 시각 ±2시간 | 월주(입춘이면 연주도)가 바뀌는 경계라는 안내 |
| 시간 모름 + 절입일 | 시각에 따라 월주가 달라진다는 안내 |

## 검증 관문 (기획서: 명식 30건이 기존 앱과 일치)

1. 기존 만세력 앱에서 명식을 조회합니다. 절기 경계일, 자시(23~01시), 시간 모름, 윤달(음력 입력), 1954~1961년생, 서머타임 기간 출생을 꼭 섞습니다.
2. `js/test-cases.js`의 `CASES`에 한 줄씩 추가합니다. 출처는 `"앱: 앱이름"` 형식으로 적습니다.
3. `check.html`을 새로고침하면 "관문 N/30"과 불일치 줄(빨간색)이 보입니다.

현재 들어 있는 9건은 손계산·기획서 예시라서 관문 수에 세지 않습니다.

## 알려진 한계

- 계산 범위는 1900~2100년입니다.
- 서머타임 시작·종료 날짜는 tz database(Asia/Seoul) 기준입니다. 시작·종료 당일 출생은 기존 앱과 다를 수 있습니다.
- 1908년 이전 한국 음력은 당시 실제 역서와 다를 수 있습니다 (현재 한국 표준시 기준으로 계산).
- 출생지는 국내 주요 도시 19곳 + 경도 직접 입력입니다. 해외 출생은 경도를 직접 넣어도 표준시가 한국 기준이라 맞지 않습니다.
- 대운수는 날수 ÷ 3을 반올림합니다. 목업 6장(목업 예시 명식)은 대운수 6, 이 앱은 5(15.4일 ÷ 3 = 5.13)라 기존 앱 대조가 필요합니다.
- 점수 · 풀이 규칙은 초안입니다. 형 · 파 · 해, 신살(도화 제외)은 아직 반영하지 않았습니다.
- 명식은 이 기기에 1개만 저장됩니다. 가족 · 지인 목록과 계정 저장은 6단계에서 붙입니다.
