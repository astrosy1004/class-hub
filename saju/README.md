# 그래프로 보는 사주 (사주 해석 웹앱)

생년월일시로 사주 명식을 계산하고, 인생 흐름을 그래프로 보여주는 웹앱입니다.
기획: `사주로 풀어보는 나의 기질 해석 앱 기획서.md` (1주 MVP 범위로 구현)

기술 구성은 `0930-weather-app/`(현장 날씨 안전도우미)과 같습니다.
순수 HTML·CSS·바닐라 JS(`<script type="module">`, 빌드 도구 없음), Firebase Auth(구글 로그인), Firestore, Firebase Hosting.

- Firebase 프로젝트: `saju-app-sykim` (표시 이름 `saju-app`, `saju-app` ID는 이미 다른 사람이 써서 사용 불가)
- 배포 주소: https://saju-app-sykim.web.app

## 단계별 진행

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 만세력 엔진: 네 기둥, 절기, 십신, 지장간, 12운성, 대운, 세운 + 검증 페이지 | ✅ 완료 |
| 2 | 입력 보정: 음력·윤달 변환, 서머타임, 출생지(경도) 선택과 안내 | ✅ 완료 |
| 3 | 화면 뼈대(`#주소` 화면 전환, 하단 탭 4개) + 입력 화면 + 결과(표 보기) | ✅ 완료 |
| 4 | 결과(아이콘 보기): 일간 본질 카드, 오행 균형, 십성 5그룹, 띠, 기질 키워드 | ✅ 완료 |
| 5 | 점수 엔진(용신·기신) + 인생 그래프 + 월별 흐름 + 한 줄 풀이 + 지금 할 일 카드 | ✅ 초안 (전문가 검수 전) |
| 6 | 구글 로그인 + 명식 저장(가족·지인 목록, Firestore) | ✅ 코드 완료 (콘솔 설정 필요) |
| 7 | Firebase Hosting 배포 + Firestore 보안 규칙 | ✅ 배포 완료 |

## 실행 방법

`<script type="module">`을 쓰므로 반드시 로컬 서버로 실행합니다.

```bash
py -m http.server 5510 --bind 127.0.0.1
```

- 앱: http://localhost:5510 (저장된 명식이 없으면 가상의 예시 명식 "홍길동"(남, 1990-03-15 10:30)으로 보여줌)
- 엔진 검증 페이지: http://localhost:5510/check.html

## 로그인 · 명식 목록 (6단계)

| 상태 | 명식 목록 저장 위치 |
|---|---|
| 로그아웃 | 이 기기 localStorage `saju:charts` (지금 보는 명식 id는 `saju:currentId`) |
| 로그인 | Firestore `users/{uid}/charts/{명식 id}` — 다른 기기에서도 보임 |

- 명식 목록 화면 `#charts`: 만세력 결과 화면 오른쪽 위 목록 버튼, 홈 인사말 아래 "명식 바꾸기", 나의 기질 화면 아래에서 들어갑니다.
  누르면 그 명식으로 모든 화면이 바뀌고, 연필 버튼은 수정, 휴지통 버튼은 삭제(확인 창)입니다.
- 새 명식 `#manse/new`, 지금 명식 수정 `#manse/edit`. 관계(본인·배우자·자녀·부모·형제자매·지인)를 고르고,
  본인이 아니면 "저장 동의를 받았어요" 체크가 있어야 저장됩니다 (기획서 개인정보 원칙).
- 처음 로그인하면 이 기기에만 있던 명식을 계정으로 올립니다. 명식 id가 같으면 덮어쓰므로 여러 번 로그인해도 늘어나지 않습니다.
- 5단계까지 쓰던 `saju:profile`(명식 1개)은 처음 열 때 목록(관계 "본인")으로 옮기고 지웁니다.
- Firebase SDK를 못 불러오면 "로그인을 불러오지 못했어요"만 보이고, 나머지는 이 기기 저장으로 그대로 동작합니다.

파일: `js/firebase.js`(SDK CDN · 설정값, SDK를 부르는 유일한 파일) · `js/auth.js`(로그인) · `js/cloud.js`(Firestore 명식 목록) · `firestore.rules`

**보안 규칙** (`firestore.rules`): `users/{uid}` 아래 전부를 그 uid 본인만 읽고 쓸 수 있습니다 (날씨 앱과 같은 규칙).
생년월일시는 Firestore가 저장할 때 암호화하고(Google 기본), 규칙으로 본인 외 접근을 막습니다. 별도 앱 암호화는 하지 않습니다.

### Firebase 콘솔 설정 (최초 1회)

`gcloud`가 없어서 CLI로 켤 수 없는 두 가지는 콘솔에서 직접 켭니다.

1. [Firestore](https://console.firebase.google.com/project/saju-app-sykim/firestore) → **데이터베이스 만들기** → 위치 `asia-northeast3 (서울)` → **프로덕션 모드**로 시작
2. [Authentication](https://console.firebase.google.com/project/saju-app-sykim/authentication) → 시작하기 → **로그인 방법** → **Google** 사용 설정 → 지원 이메일 선택 → 저장
3. Authentication → 설정 → **승인된 도메인**에 `localhost`가 있는지 확인 (없으면 `localhost`, `127.0.0.1` 추가)
4. 보안 규칙 배포: 이 폴더에서

```bash
firebase deploy --only firestore:rules
```

웹 앱 등록(`saju-app`, appId `1:642552513638:web:60e11a4a3ade417f0019a7`)은 CLI로 이미 했고 설정값은 `js/firebase.js`에 있습니다.

## 배포 (Firebase Hosting)

```bash
firebase deploy --only hosting,firestore:rules   # 이 폴더(saju/)에서 실행
```

- 이 폴더 자체(`.`)를 올리고, 아래 파일은 `firebase.json`의 `ignore`로 **공개하지 않습니다**:
  기획서·README(`*.md`), 목업 PDF(`*.pdf`), 엔진 검증 페이지(`check.html`, `css/check.css`, `js/check.js`, `js/test-cases.js`), 설정 파일, 점(.)으로 시작하는 파일

- `saju-app-sykim.web.app` · `saju-app-sykim.firebaseapp.com`은 Authentication 승인된 도메인에 기본으로 들어 있어 배포 주소에서도 구글 로그인이 됩니다.

## 인생 주요 포인트 · 건강 (수정 요청 반영)

- **인생 주요 포인트** (`lifeEvents`, 규칙은 `score-rules.js`의 `LIFE_EVENTS`): 해마다 대운 40% + 세운 60%로 영역 점수를 매기고,
  그해 천간 십신 · 일지(배우자궁)와 육합 · 도화 가점을 더해 고릅니다.
  - 결혼·인연(연애·배우자 영역, 22~60세, 여자는 정관·남자는 정재 해 가점, 26~38세 가점) · 취업·승진(직업, 20~67세) · 경제적 성취(재물, 25~80세): 점수가 높은 해 3개
  - 건강 주의(건강, 30~85세): 점수가 낮은 해 2개. 고른 해끼리는 4~5년 이상 떨어지게 합니다.
  - 인생 그래프 아래 줄마다 표시(지난 해는 흐리게), 목록의 해를 누르면 그해 운세로 이동, 그해 운세 화면에도 "그해의 인생 포인트"로 표시
- **건강운** 영역(마음 영역을 대신함): 식신·정인 가점, 편관(칠살)·상관 감점, 조후 충족 가점, 원국에 없는 오행이 들어오면 가점 · 넘치는 오행이 더 들어오면 감점, 일지 충 감점
- **타고난 건강 체크** (`healthCheck`): 오행이 없거나(0개) 많을수록(3개 이상), 기신일수록 "살펴볼 곳" 점수가 높습니다. 오행별 몸 대응은 `ORGANS`.

## 생년월일 입력

연도(올해 → 1900년, 10년 단위 묶음 · 띠 표시) · 월 · 일 목록으로 고릅니다. 일 목록은 양력이면 그 달 날수와 요일,
음력이면 그 음력 달의 날수(29·30일)로 자동으로 바뀝니다. 고른 날짜 아래에 요일 · 음력(또는 양력 변환 날짜)과
그해 윤달이 바로 보이고, 없는 윤달을 고르면 경고합니다. 시각은 시 · 분 목록이며 대략 어느 시(時)인지 함께 보여줍니다.

## 점수 엔진 (`js/score.js`, 규칙은 `js/score-rules.js`)

기획서 "해석 엔진 로직" 그대로: **용신에 가까울수록 높고, 기신에 가까울수록 낮다**. 같은 명식이면 항상 같은 점수.

1. 원국 분석: 자리별 무게(월지 3배) × 지장간 비중으로 나를 돕는 기운(비겁·인성) 비율 50% 이상이면 신강.
   겨울(亥子丑)생은 조후 용신 화, 여름(巳午未)생은 수. 그 외엔 신강이면 식상·재·관 중 가장 약한 것, 신약이면 인성.
   희신 = 용신을 생하는 오행, 기신 = 신강이면 인성·비겁(신약이면 재·관) + 용신을 극하는 오행.
2. 기본 점수: 천간 40% + 지지(지장간 비중) 60%, 용신 1 · 희신 0.6 · 한신 0 · 기신 -0.8 → 52 ± 34점
3. 영역 가중치: 영역별 십신 가중치 (재물 = 재성·식상 +, 비겁 - 등, 성별에 따라 연애·자식 다름)
4. 관계 보정: 일지(배우자궁) · 시지(자녀궁)와 육합 가점, 충 감점. 천간합으로 용신이 생기면(무계합화 등) 가점. 도화, 조후
5. 월운은 세운 35% + 월운 65%, 일진은 일진 70% + 월운 30%

기획서 예시(병진·신축·계유·신유)는 신강 · 조후 용신 화 · 희신 목 · 기신 금·수로 나와 기획서와 같습니다.
**규칙 숫자는 초안**이며, 기획서대로 출시 전 명리 전문가 검수로 `score-rules.js`를 보정해야 합니다.

### 운영 원칙 반영

- 모든 결과 화면 하단에 참고용 고지
- 재물: 종목·매수·매도 추천 없이 "투자 이유 · 세금 · 자금 용도" 점검 안내
- 건강: 오행별 "살펴볼 곳"만 보여주고, 모든 건강 화면에 "의학적 진단이 아니에요" 문구와 국가 건강검진 안내를 둠
- 관계: "이혼수", "자식 복 없음" 같은 단정 표현을 문구에 쓰지 않음

## 만세력 계산 기준 (`js/manse.js`)

| 항목 | 기준 |
|---|---|
| 연주 | 입춘 **시각**에 해가 바뀜 (1984년 = 甲子) |
| 월주 | 12절(입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한) **시각**에 달이 바뀜. 甲己년은 丙寅월부터 |
| 일주 | 출생지 지방시 날짜 기준, **23시(자시 시작)부터 다음 날**. 2000-01-01 = 戊午일 |
| 야자시 옵션 | 켜면 23~24시는 일주를 그날로 두고, 시주만 다음 날 일간으로 계산 |
| 시주 | 지방시 2시간 단위. 서울(동경 126.98°)은 표준시보다 약 32분 늦게 바뀜 (자시 23:32~01:32) |
| 시간 모름 | 시주를 비우고 정오 기준으로 연·월·일주 계산 |
| 표준시 | 1908~1911, 1954-03-21~1961-08-09는 UTC+8:30, 나머지 UTC+9 |
| 서머타임 | 1948~1951, 1955~1960, 1987~1988 기간(`KOREA_DST`)이면 1시간을 빼고 계산. 끌 수 있음 |
| 음력 입력 | `lunar.js`로 양력으로 바꾼 뒤 계산. 없는 윤달·없는 날짜는 오류 문구 |
| 십신 | 지지는 정기(子=癸, 午=丁, 巳=丙, 亥=壬) 기준 |
| 대운 | 양남음녀 순행, 음남양녀 역행. 대운수 = 출생~절입 날수 ÷ 3, 반올림, 최소 1 |
| 대운 나이 | 세는 나이 기준. 현재 대운 = (올해 − 출생 연도 + 1)이 속한 대운 |

학파마다 다른 선택(대운수 반올림, 대운 개수, 기본 경도)은 `saju-data.js`의 `SETTINGS`에서 바꿉니다.

## 절기 정확도

`solar-terms.js`는 Meeus 『Astronomical Algorithms』 25장의 고정밀 방법(VSOP87 축약 계수 + 장동·광행차)과
ΔT 다항식으로 절입 시각을 계산합니다. 공개된 절입 시각 8건(2023~2026 입춘, 2024 춘분·하지·추분·동지)과
비교해 **최대 오차 0.6분**입니다. (처음 쓴 저정밀 식은 최대 10분 틀려서 바꿨습니다.)

## 한국 음력 (`js/lunar.js`)

음력표를 넣지 않고 천문 계산으로 만듭니다.

1. 합삭(새달) 시각을 Meeus 49장 공식으로 계산하고, 합삭이 든 **한국 표준시 날짜**를 초하루로 둡니다.
2. 동지가 든 달을 11월로 두고, 동지~다음 동지 사이에 달이 13개면 중기(우수·춘분·곡우…)가 없는 첫 달을 윤달로 둡니다.

중국 음력표(UTC+8 기준)를 쓰면 합삭이 한국시간 자정 근처인 달에 한국 음력과 하루씩 어긋납니다.
예: 1966년 설날 합삭은 한국시간 1월 22일 00:46이라 한국은 1/22, 중국은 1/21입니다.

검증: 설날 7개 해, 추석 3개 해, 윤달 13개 해(1995~2028)가 맞고, 1900~2100년 모든 날짜를 양력→음력→양력으로 왕복해 오류 0건입니다.

## 보정 안내 (`notices`)

결과가 갈릴 수 있는 경우 결과 위에 안내를 띄웁니다. 기준값은 `SETTINGS`에 있습니다.

| 경우 | 안내 |
|---|---|
| 서머타임 기간 출생 | 1시간을 뺐다는 안내 (끄면 보정하지 않았다는 안내) |
| 1954~1961년 등 UTC+8:30 시기 | 당시 표준시를 반영했다는 안내 |
| 시간을 입력함 | 출생지 경도로 지방시가 몇 분 다른지, 지방시 몇 시로 시주를 정했는지 |
| 시주가 바뀌는 시각 ±10분 | 출생 시각 확인 요청 |
| 23시대 출생 | 일주를 다음 날로 봤다는 안내 (야자시면 그 반대) |
| 절입 시각 ±2시간 | 월주(입춘이면 연주도)가 바뀌는 경계라는 안내 |
| 시간 모름 + 절입일 | 시각에 따라 월주가 달라진다는 안내 |

## 검증 관문 (기획서: 명식 30건이 기존 앱과 일치)

1. 기존 만세력 앱에서 명식을 조회합니다. 절기 경계일, 자시(23~01시), 시간 모름, 윤달(음력 입력), 1954~1961년생, 서머타임 기간 출생을 꼭 섞습니다.
2. `js/test-cases.js`의 `CASES`에 한 줄씩 추가합니다. 출처는 `"앱: 앱이름"` 형식으로 적습니다.
3. `check.html`을 새로고침하면 "관문 N/30"과 불일치 줄(빨간색)이 보입니다.

현재 들어 있는 9건은 손계산·기획서 예시라서 관문 수에 세지 않습니다.

## 알려진 한계

- 계산 범위는 1900~2100년입니다.
- 서머타임 시작·종료 날짜는 tz database(Asia/Seoul) 기준입니다. 시작·종료 당일 출생은 기존 앱과 다를 수 있습니다.
- 1908년 이전 한국 음력은 당시 실제 역서와 다를 수 있습니다 (현재 한국 표준시 기준으로 계산).
- 출생지는 국내 주요 도시 19곳 + 경도 직접 입력입니다. 해외 출생은 경도를 직접 넣어도 표준시가 한국 기준이라 맞지 않습니다.
- 대운수는 날수 ÷ 3을 반올림합니다. 목업 6장의 예시 명식은 대운수 6, 이 앱은 5(15.4일 ÷ 3 = 5.13)라 기존 앱 대조가 필요합니다.
- 점수 · 풀이 규칙은 초안입니다. 형 · 파 · 해, 신살(도화 제외)은 아직 반영하지 않았습니다.
- 로그인 후 로그아웃하면 이 기기 목록(로그인 전 것)만 보입니다. 로그인 중에 추가·수정한 명식은 계정에만 있습니다.
